# RL Fine-Tuning of Sequential Recommendations — KION / Java 21

**Исследовательский проект на Java 21 и Maven.** Обучение небольшого GPT-2-подобного sequential recommender, модели вознаграждения и трёх RL-политик на **реальных взаимодействиях KION**. Исследуется компромисс между релевантностью, модельной оценкой досмотра, разнообразием и повторениями.

> **Главный результат.** RL-novelty по сравнению с базовой моделью повысил **предсказанное** вознаграждение на **3,95%** и NDCG@10 на **2,19%**, но снизил Recall@10 на **5,63%**. Reward reranking повысил предсказанный reward на **9,21%**, однако стал ставить один и тот же фильм на первое место всем 314 тестовым пользователям. Эти различия измерены на одном seed и ограниченной выборке; они не доказывают роста реальной удовлетворённости.

## Исследовательский вопрос

**Можно ли с помощью policy-gradient RL увеличить ожидаемую долю досмотра фильмов, сохранив приемлемую релевантность последовательных рекомендаций?**

Проверяем четыре предположения:

1. RL может увеличить предсказанный reward, но необязательно улучшит Recall/NDCG.
2. KL-регуляризация ограничивает отклонение от базовой политики и влияет на компромисс.
3. Бонус новизны способен влиять на частоту повторов и разнообразие выдачи.
4. Пятишаговая генерация по собственным предсказаниям создаёт синтетические состояния, которые нельзя считать реальными пользовательскими историями.

## Данные и предотвращение утечек

Источник: [официальный MTS KION dataset](https://github.com/irsafilo/KION_DATASET), архив `interactions.csv.zip`. Программа в проведённом запуске прочитала **1 594 787 CSV-записей** из скачанного архива (это число относится именно к использованному файлу, не заявляется как полный размер всей коллекции KION).

**Глобальный временной протокол:**

| Split | Интервал | Примеры в итоговом эксперименте |
|---|---|---:|
| Train | до 2021-08-09 (не включительно) | 2 000 |
| Validation | 2021-08-09 — 2021-08-15 | 350 |
| Test | 2021-08-16 — 2021-08-22 | 314 |

- Отбор 5 000 пользователей и словаря из 300 фильмов построен только по **train**.
- Для события-цели используются только взаимодействия из **строго более ранних календарных дней**. В KION нет точного порядка внутри одного дня; текущая реализация канонически упорядочивает такие объекты по ID для будущего контекста, **не трактуя это как фактический временной порядок**.
- Один target на пользователя в validation и test; один и тот же набор test примеров оценивает все политики.
- Из рассмотрения исключены события с фильмами вне train-каталога. Счётчик **17 067** в логе отражает события вне выбранного словаря при построении примеров, включая train; это **не количество исключительно тестовых объектов**.
- Следовательно, результаты характеризуют **условное качество на сокращённом warm-catalog**, а не на полном каталоге сервиса. При одном target на пример Recall@10 численно совпадает с HitRate@10.

## Модели и RL

### 1. Исходная GPT-2-style sequential model (SFT)

С нуля обучается компактный causal decoder Transformer, где **токен — ID фильма**. Архитектура включает token/position embeddings, один pre-LayerNorm Transformer block, causal multi-head self-attention, residual connections, FFN с GELU, финальный LayerNorm и output head с разделяемыми embedding-весами. Это **уменьшенная GPT-2-подобная модель**, **не** pretrained GPT-2 и **не** полный оригинальный GPT-2.

Для реальной истории `h` и следующего просмотренного фильма `a*` минимизируется `L_SFT = -log π_SFT(a* | h)`.

### 2. Reward model

Латентно-факторная модель с историей:

`R_phi(h,a) = sigmoid(b_0 + b_a + <avg_embeddings(h), embedding(a)> / sqrt(d))`.

Цель: `r = clip(watched_pct / 100, 0, 1)`. Reward model обучается по наблюдавшимся просмотрам с MSE и **замораживается** на стадии RL. Её оценки для треков/фильмов, которые пользователи в данной ситуации не просматривали, — **предсказания**, а не реальные контрфактические исходы.

### 3. RL policy gradient

На истории `h` выбираем случайное действие `a ~ π_theta(.|h)`, затем используем REINFORCE с baseline и regularization:

`J(theta) = E[R_phi(h,a) + novelty_bonus(h,a)] − beta * KL(π_theta || π_SFT) + lambda * E[log π_theta(a*|h)]`.

KL вычисляется по **полному распределению ограниченного каталога**, но только на сэмплированных историях. `lambda = 0.20` — anchor cross-entropy, который сохраняет связь с next-item prediction. Оптимизируются реальные параметры Transformer посредством Java autodiff и Adam; это не постобработка вероятностей.

| Политика | Параметры | Идея |
|---|---|---|
| SFT | cross-entropy | Качество исходного предсказания |
| Reward reranking | top-50 от SFT → сортировка по R_phi | Контроль без RL |
| RL-lowKL | beta=0.03 | Допускаем больший сдвиг политики |
| RL-highKL | beta=0.35 | Сильнее ограничиваем отклонение от SFT |
| RL-novelty | beta=0.35; bonus=0.15 для отсутствующего в истории объекта | Проверяем поощрение новизны |

**Средняя конфигурация:** seed=42, vocab=302 с PAD/UNK, 5 000 пользователей, max_train=2000, context=8, embedding dim=12, heads=2, SFT epochs=3, reward epochs=5, RL steps=500 на каждый вариант. Это CPU-ориентированный proof-of-concept, а не промышленный рекомендатель.

## Результаты на реальном KION

Основные значения ниже взяты **не из синтетической демонстрации**, а из реального запуска `--medium`. Полный машинно-сгенерированный отчёт и CSV лежат в [`outputs/kion-medium/`](outputs/kion-medium/).

### Reward model на наблюдавшихся взаимодействиях

| Split | MAE ↓ | RMSE ↓ | N |
|---|---:|---:|---:|
| Validation | 0.35946 | 0.39212 | 350 |
| Test | 0.36581 | 0.39391 | 314 |

Ошибка достаточно велика относительно целевой переменной в диапазоне [0, 1]. **Сравнение с константной или popularity-based reward baseline не проводилось**, поэтому нельзя утверждать, что эта модель уверенно предсказывает пользовательские предпочтения. Рост `predicted_reward` нужно интерпретировать с осторожностью.

### Сравнение рекомендательных политик — один и тот же test

| Policy | Recall@10 ↑ | NDCG@10 ↑ | Predicted reward (Top-1) ↑ | Catalog coverage@10 ↑ | Max Top-1 share ↓ | History repeat@10 ↓ |
|---|---:|---:|---:|---:|---:|---:|
| SFT | **0.2261** | 0.1140 | 0.5887 | 0.0600 | 0.3535 | 0.0768 |
| Reward reranking | 0.1656 | 0.1064 | **0.6429** | 0.0433 | **1.0000** | 0.0640 |
| RL-lowKL | 0.1815 | 0.0962 | 0.5989 | **0.1300** | 0.4459 | **0.0691** |
| RL-highKL | 0.2038 | 0.1122 | 0.6073 | 0.0767 | 0.4682 | 0.0752 |
| RL-novelty | 0.2134 | **0.1165** | 0.6119 | 0.0767 | 0.5350 | 0.0748 |

*Оговорка к заголовкам:* для `max_top1_share` и `history_repeat@10` меньшие значения **не всегда означают лучшее пользовательское качество**. Повторное просматривание фильма иногда осмысленно, а высокая концентрация сама по себе не доказывает некачественную рекомендацию; здесь это диагностические признаки.

### Сопоставление с SFT

| Политика | Δ predicted reward | Δ NDCG@10 | Δ Recall@10 |
|---|---:|---:|---:|
| Reward reranking | +9.21% | −6.66% | −26.76% |
| RL-lowKL | +1.74% | −15.63% | −19.72% |
| RL-highKL | +3.17% | −1.60% | −9.86% |
| RL-novelty | +3.95% | +2.19% | −5.63% |

**Наблюдения:**

1. **Оптимизация reward не равна оптимизации релевантности.** Reranking максимизирует score reward model относительно SFT, но снижает Recall и NDCG. В этом запуске он рекомендует **один и тот же Top-1 фильм всем 314 пользователям** (max Top-1 share = 1.0, unique Top-1 = 1), то есть произошёл коллапс персонализации по верхней позиции.
2. **RL-lowKL** расширяет каталожное покрытие (6% → 13%), но хуже сохраняет релевантность. **RL-highKL** сохраняет NDCG ближе к базовому уровню, хотя также снижает Recall; это соответствует назначению KL-регуляризации, но не доказывает, что именно beta стало причиной эффекта в среднем по многим seed.
3. **RL-novelty** показал лучший NDCG среди протестированных вариантов и более высокое predicted reward, чем SFT, **при снижении Recall**. Рост NDCG всего 0.0025 в абсолютных единицах, поэтому говорить об убедительном повышении качества без повторов с другими seed нельзя.
4. Результаты зависят от размера подвыборки и случайности. Предыдущий короткий запуск служил проверкой устойчивости конвейера, **не должен смешиваться** с результатами финального medium-профиля.

## Пятишаговая генерация

Пять раз выбираем top-1 рекомендацию и подставляем её как очередной токен истории, **не проверяя фактическое взаимодействие пользователя**:

| Policy | Step 1 | Step 2 | Step 3 | Step 4 | Step 5 |
|---|---:|---:|---:|---:|---:|
| SFT | 0.5887 | 0.5716 | 0.5946 | 0.5966 | 0.5980 |
| RL-lowKL | 0.5989 | 0.5896 | 0.5957 | 0.5974 | 0.5986 |
| RL-highKL | 0.6073 | 0.5776 | 0.5954 | 0.5972 | 0.5985 |
| RL-novelty | 0.6119 | 0.5911 | 0.5962 | 0.5978 | 0.5990 |

**Интерпретация:** у каждого варианта нет монотонного роста reward по горизонту. Эти числа — лишь **предсказанные** reward model оценки в искусственных состояниях. После первого шага история уже может перестать соответствовать действительности. Для оценки реального качества на горизонте 5 нужен симулятор пользовательских действий с проверенным качеством или онлайн-эксперимент.

## Обсуждение долгосрочных целей и ограничений

Возможная **дальнейшая гипотеза**, не реализованная и не измеренная в текущем проекте:

`r_long = alpha * completion_rate + beta * return_within_7_days + gamma * future_meaningful_views - delta * repetitive_recs`.

Для такого сигнала можно брать долю просмотра, число следующих осмысленных взаимодействий и появление нового просмотра на последующих днях. В офлайне можно проверить **предсказательную способность** таких прокси на хронологически отложенных реальных сессиях с учётом right-censoring и сравнить разные reward-модели. Однако наблюдательные логи не показывают, что произошло бы **после другой рекомендательной политики**. Для причинного вывода об удержании и удовлетворённости необходим online A/B-тест либо строгие предпосылки off-policy evaluation, для которых в этих логах нет известных вероятностей показа.

Ограничения реализации:

- Очень малые Transformer и каталог (300 фильмов), только **314** тестовых примеров, один seed; различия могут быть случайными.
- Reward model обучена на выбранных просмотрах; не известны пропущенные, показанные и отвергнутые альтернативы, поэтому возможны exposure bias и reward hacking.
- `watched_pct` — ограниченный proxy, не то же самое, что удовлетворённость или long-term retention.
- Из каталога исключены редкие и не встречавшиеся в train объекты; на полном KION значения метрик будут другими.
- В датах нет внутридневного порядка; `item_id` при построении контекста задаёт лишь детерминированное представление одного дня.
- Автоматическая генерация пяти фильмов не моделирует настоящие реакции пользователя.
- Не проводились repeated-seed evaluation, статистические интервалы и сравнение reward RMSE с простым константным baseline; это направления обязательного усиления работы при наличии времени.

## Запуск на Windows

Требования: **JDK 21+**, Maven 3.9+; работа на **Java 25 runtime** с bytecode Java 21 поддерживается. Никаких Python, PyTorch и GPU не требуется.

В терминале CMD из корня проекта:

```cmd
java -version
mvn clean package
java -Xmx4g -jar target\kion-rl-java-1.0.0.jar --medium --output outputs\kion-medium
```

Первый запуск автоматически пытается скачать KION. Чтобы явно указать локальный архив:

```cmd
java -Xmx4g -jar target\kion-rl-java-1.0.0.jar --medium --data data\kion-data.zip --output outputs\kion-medium
```

Для быстрой проверки конвейера (**только синтетика, не использовать для выводов**):

```cmd
java -cp target\classes ru.research.kion.Experiment --demo --sft-epochs 1 --rl-steps 10
```

Готовый JAR также находится в корне проекта: `java -Xmx4g -jar kion-rl-java-1.0.0.jar --medium`.

*Результаты не детерминированы побитово между платформами; seed фиксирует основные генераторы случайных чисел, но не является универсальной гарантией идентичности всех запусков.*

### Тест численных градиентов

```cmd
java -cp target\classes ru.research.kion.Diagnostics
```

Эта проверка сравнивает autodiff с конечными разностями, но не заменяет полноценные программные тесты.
